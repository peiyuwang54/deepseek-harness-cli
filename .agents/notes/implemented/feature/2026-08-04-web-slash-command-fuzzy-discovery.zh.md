# Agent Note: Web 斜杠命令模糊发现

Status: implemented

[English](2026-08-04-web-slash-command-fuzzy-discovery.md) | 中文

## 问题

Web 斜杠菜单的部分候选组要求按名称前缀匹配，因此用户只记得关键字母却不记得其准确位置时，就无法发现条目。扩大菜单的匹配范围可使发现更容易，但命令与 skill 的执行仍必须保持精确匹配和确定性：近似输入行绝不能执行相近条目。

## 决策

`/` 命令与 skill source 都会把候选交给 `ui-primitives` 共享的 `rankByName` 辅助函数；该函数将键入的查询作为不区分大小写的有序子序列，与名称进行模糊匹配。精确前缀构成排名最高的一类匹配。在每类匹配中，对齐分数越高越优先：分隔符边界和相邻字符会提高分数，前导字符和间隔会降低分数；分数相同则保持各 source 的目录顺序。命令位置过滤仍会在排名前从行内菜单中移除接收参数的命令。

评分器对每个候选项使用动态规划，时间复杂度为 `O(query length × name length)`，空间复杂度为 `O(name length)`。候选项评分只在客户端进行且只检查名称；描述不影响匹配。菜单选择仍派发所选的精确名称，而命令的空格键／Enter 键判定和宿主 skill 注入仍要求 token 精确匹配。

## 考虑过的替代方案

**保留仅前缀匹配。** 否决，因为本功能要解决的用户无法准确回忆前缀的问题依然存在：`/cpt` 无法发现 `/compact`。

**匹配无序字符或描述。** 否决，因为无序匹配难以预测，而描述匹配可能展示命令，但命令的可见名称无法解释其排名。

**使用通用模糊搜索依赖。** 否决，因为该界面只需对小型命令目录使用一种受限的子序列规则；可配置搜索索引会增加 bundle 体积，并引入产品未使用的排名行为。

## 后果

用户可以凭按顺序记得的字母发现命令与 skill；只要目录相同，排名就保持稳定。评分刻意采用启发式规则：与分隔符对齐的匹配可能排在原始跨度更短的匹配之前。共享辅助函数与 source 测试固定各项排名因素以及同分时的稳定顺序，组装后的 Web 场景则固定 `/cpt` 解析为 `/compact`，以及 `/plcy` 列出相匹配的 skill 集合。精确执行语义保持不变。
