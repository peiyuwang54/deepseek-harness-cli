# Agent Note: Ship the interactive TUI as a first-class CLI profile

Status: implemented

English | [中文](2026-08-14-shipped-tui-cli-front-door.zh.md)

## Problem

DeepSeek Harness retained a shipped Web application and one-shot/headless entry points, but no longer shipped an interactive terminal application. The earlier `@deepseek-ai/dsh-tui` implementation had been removed because it had no product composition, so keeping its renderer alone would again create an unsupported frontend. A terminal command must therefore prove the entire product boundary: CLI selection, Loader composition, exact Agent ownership, session restore, model routing, approvals and questions, terminal lifecycle, and package publication.

The restored frontend also had to target the current Harness APIs. Since its deletion, Cordis imports moved to the DeepSeek fork, model selection became a captured `ModelSelection`, user interaction split into `userQuestions` and `approval`, compaction and session-reference services changed names, Agent events adopted payload objects, and prompt-admission/inbox event shapes changed. Treating the historical source as current would compile only partially and would violate newer lifecycle and audit contracts.

## Decision

The CLI ships `dsh tui` as an alias of the app-owned `tui` profile. That profile composes `base + @deepseek-ai/dsh-tui-app`; it does not replace or alter the Web and headless profiles. `@deepseek-ai/dsh-tui-app` owns command-line startup and one exact root Agent identity, while `@deepseek-ai/dsh-tui` remains a presentation/input package that mounts onto an already created or resumed Agent.

Startup publishes either a fresh `main-session-<uuid>` identity or the requested `--resume` identity before the dependency-heavy runner activates. The runner waits for Loader settlement, installs the configured model selection during unpublished Agent setup, creates or resumes that exact identity, mounts the renderer, then removes the bootstrap selection so the TUI's `/model` controller is authoritative. Fresh setup resolves and records the effective default agent preset before mounting it; resume setup mounts `resolveSessionPreset(session)`, so a Web-originated session with a later durable blank-session switch regains that historical composition rather than today's default. The bundle disables every base model-facing row owned by the preset roster, so the selected preset is the only source of those capabilities and `minimal` does not inherit the standard/code stack. The prompt registry is a separately addressable `@deepseek-ai/dsh-tui/prompt` Loader row mounted before the runner. Normal startup requires TTY stdin and stdout and fails early otherwise; `--help` remains pipe-safe. Pipes and automation use the existing headless profile.

Settings and workspace state are Host-plane product services, not browser ownership. The TUI profile composes the same file settings provider and `ui-theme.preference` schema as Web plus the same JSON storage/domain/workspace registry stack. `/settings` is a redacted namespace/document hub rather than a clone of the Web React forms, and `/theme` mutates only the preference field so a redacted sibling secret can never be erased by section replacement. `/workspace` reads the durable registry and requests a fresh-session handoff; it never rewrites the bound session's immutable `SessionHeader.cwd`.

One CLI-owned process host implements both resume and fresh-workspace transitions. The renderer validates idle/session/directory state, flushes the current session, drains input, and releases pi-tui plus alternate-screen/mouse modes; the host then preserves the selected profile, patch stack, environment, and session argument while replacing the process in the destination directory (or supervising a foreground child on platforms without `execve`). All recoverable validation precedes committed teardown. A rejected pre-commit handoff re-enters terminal modes and forces a complete frame because pi-tui's previous-row cache otherwise belongs to the abandoned alternate buffer. The `start(cwd)` method is optional at the renderer seam, preserving resume-only custom embeddings even though the shipped host implements both methods.

The renderer is recovered from DeepSeek Harness's own pre-deletion history and ported to current APIs. Canonical `Session` events remain the sole durable conversation source: replay folds those events into committed terminal output, while live chunks, tool progress, questions, and approvals are transient projections. The TUI does not add another chat log or tool scheduler. It consumes the existing scoped command registry, Agent inbox operations, session query/reference services, skill registry, tool presenters, token meter, and model-selection seam.

Approval policy and execution remain owned by `ctx.approval`. The TUI registers only an exact-agent, FIFO answerer for `approval/request`, returning `allowed-once`, `rejected`, `cancelled`, or `unavailable`; the Approval service owns the durable `approval/asked` and `approval/decided` audit pair. The shared Permission service contributes `/permissions` plus the Codex-inspired `/yolo` shortcut. Bare `/permissions` opens a terminal selector over the service-owned preset table, while an argued invocation and every selection use the same command handler as Web. The dashboard and footer project the configured preset display name from that service. `/yolo` resolves the deployment's preset combining `danger-full-access` with `never` and writes through the same sandbox and live Approval setters; the explicit command is the confirmation, while its settlement names the prior selectable preset's recovery command. `ctx.userQuestions` remains the independent structured-question provider. Both interaction queues share the renderer's modal queue without becoming lifecycle or policy authorities.

Terminal rendering keeps stable history separate from live projection, preserves pre-first-token and per-phase timing, reorders an empty Assistant row behind claimed user/context messages, renders tool-owned presentation intents, supports session resume and scoped skills, and restores raw mode on disposal. Width-keyed card caches avoid re-wrapping settled output on every frame, while one forward timing cursor serves every step footer without rescanning the complete log. Color-scheme or reasoning rebuilds retain the current streaming component and invalidate its timing cache, so a mid-turn redraw cannot lose accumulated response time.

The shipped presentation defaults to the alternate screen and treats transcript position as explicit view state: a bounded viewport follows new output until Page Up/Page Down or the mouse wheel moves away, then resumes tail-following when the user returns with Ctrl+End or reaches the newest page. Alternate-screen and SGR mouse modes enter before pi-tui starts and leave only after it stops; startup failure, normal disposal, and process handoff use the same restoration boundary. The existing multiline editor, bracketed paste, and cursor-aware `@` completion remain the input authority. `/model`, Alt+M, and the footer's mouse target all enter the same model controller, so the shortcut and visual affordance cannot diverge from command behavior.

A true zero-state session uses an adaptive dashboard rather than stretching the compact transcript header across an empty viewport. It renders a Braille-cell raster derived from the first-party official SVG mark, projects the composed agent preset, selected model, and permission state from their owning services, and summarizes the newest queryable sessions plus command-owned quick actions. The raster has full, reduced, and wordmark-only height tiers without depending on Kitty/iTerm image protocols. The first durable turn contracts it to the ordinary header, so no duplicate welcome state survives into conversation. The multiline editor owns one complete frame whose footer carries state-sensitive send/steer hints; a separate bottom bar aligns workspace and usage against agent status, model, context pressure, and queued work.

Rich output remains terminal-native rather than importing the Web React tree. pi-tui's GFM renderer owns headings, emphasis, links, nested/task lists, blockquotes, tables, and fenced code; a narrow highlighter maps `diff`/`patch` metadata, hunks, removals, and additions to the same semantic palette used by tool diff cards. Adjacent hunks for one path form one visual group. KaTeX typesetting, fetched Markdown images, Shiki token coloring, copy controls, and horizontal scrollers remain explicit browser-only differences instead of hidden dependencies in the terminal package.

## Reference and provenance boundary

Gemini CLI and OpenAI Codex were studied for process-mode separation, terminal input routing, committed-versus-live rendering, approvals, resume, headless output discipline, and PTY testing. Their Apache-2.0 licensing would permit attributed reuse, but this implementation copies no source from either repository. Official Claude Code and the inspected third-party source reconstruction are all-rights-reserved; only high-level observable behavior was considered and no code or nontrivial expression was copied. `@earendil-works/pi-tui` remains an explicit dependency with its local compatibility patch and generated third-party notice.

The restored TUI snapshot is first-party DeepSeek Harness source from commit `7248b5ec8f8769f882f12fd521504fa48e97bcf3`, immediately before deletion commit `10bb9cbf4a22b5095bb9ff04d1425907af8f08af`. At that point both the repository and `@deepseek-ai/dsh-tui` declared BSD 3-Clause. The repository-wide MIT adoption in `c905c4694e317eff1f529f0fed047c2ce202d11a` happened after the package had been deleted and therefore did not carry that historical snapshot through the mechanical package-manifest relicensing. The restored implementation retains its BSD 3-Clause terms; the current adaptations and additions are MIT-licensed. The combined package consequently declares the exact SPDX expression `(MIT AND BSD-3-Clause)`, and its package-local `LICENSE` preserves both notices and explains the boundary.

## Verification

The renderer is covered by pure utility tests, Agent/session integration tests, real approval-service tests, ANSI-aware headless-terminal component tests, and keyless terminal-state snapshots. A dedicated zero-state checkpoint pins the centered dashboard, real status labels, recent-session projection, framed editor, and bottom bar; an interaction test pins its contraction on the first turn. The permission selector and a committed preset switch have terminal-state checkpoints over the real command and projection services. Settings, Appearance, the workspace picker, and failed-handoff recovery each have a terminal-state checkpoint; interaction tests pin field-only theme mutation, settings-document discovery, immutable cwd, and the pre-await single-flight latch under repeated Enter. The app bundle has startup, identity, non-TTY, preset-safe Agent creation/resume, and patch-shape tests. CLI tests cover the alias, profile selection, help, non-TTY failure, shipped config, replacement argument fidelity, validation-before-shutdown, POSIX exec, and supervised-child fallback. Package typecheck, host typecheck, Loader/config constraints, package publication constraints, generated catalogs, documentation links, licenses, and third-party notices are required gates.

## Alternatives considered

**Keep Web as the only interactive product.** Rejected because the requested deployment is an interactive CLI and Web cannot satisfy terminal-native workflows, piping boundaries, or SSH/tmux usage.

**Put Agent creation inside the renderer.** Rejected because it makes a UI package a lifecycle authority, races Loader listeners, and prevents the bundle from proving exact create/resume identity before presentation mounts.

**Copy a complete external CLI frontend.** Rejected because those frontends couple to different runtimes and data models; Claude-family source also cannot be copied under its license. Reusing the Harness-owned renderer preserves native Session, Tool, Command, Approval, and Cordis contracts.

**Embed the Web React settings and conversation tree in a terminal shim.** Rejected because it would pull browser transport, DOM layout, and client-side state ownership across the Host boundary. The TUI instead consumes the same settings, workspace, preset, and session services and gives them terminal-native selectors and renderers.

**Make TTY detection silently fall back to headless.** Rejected because redirecting an interactive command would change its protocol and approval semantics. The explicit profile is the boundary: `tui` requires a terminal, `headless` is for automation.

## Consequences

DeepSeek Harness once again has a supported interactive terminal product, invoked with `dsh tui`, while `dsh web`, `--profile headless`, ACP, and other front doors remain independent. The product adds a renderer package, a shipped bundle, a pi-tui patch, terminal snapshots, and platform lifecycle obligations. A new Cordis service/catalog and package-publication surface must therefore remain generated and tested. The TUI is intentionally text-terminal only and has no cross-process session lock. The shipped CLI owns process replacement for `/resume` and `/workspace`; a custom renderer embedding that omits those callbacks degrades to warnings without changing the current session.
