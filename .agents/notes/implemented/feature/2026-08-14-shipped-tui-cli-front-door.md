# Agent Note: Ship the interactive TUI as a first-class CLI profile

Status: implemented

English | [中文](2026-08-14-shipped-tui-cli-front-door.zh.md)

## Problem

DeepSeek Harness retained a shipped Web application and one-shot/headless entry points, but no longer shipped an interactive terminal application. The earlier `@deepseek-ai/dsh-tui` implementation had been removed because it had no product composition, so keeping its renderer alone would again create an unsupported frontend. A terminal command must therefore prove the entire product boundary: CLI selection, Loader composition, exact Agent ownership, session restore, model routing, approvals and questions, terminal lifecycle, and package publication.

The restored frontend also had to target the current Harness APIs. Since its deletion, Cordis imports moved to the DeepSeek fork, model selection became a captured `ModelSelection`, user interaction split into `userQuestions` and `approval`, compaction and session-reference services changed names, Agent events adopted payload objects, and prompt-admission/inbox event shapes changed. Treating the historical source as current would compile only partially and would violate newer lifecycle and audit contracts.

## Decision

The installed `deepseek` command boots the app-owned `tui` profile by default; `dsh tui` remains its compatibility spelling. That profile composes `base + @deepseek-ai/dsh-tui-app`; it does not replace or alter the Web and headless profiles. `@deepseek-ai/dsh-tui-app` owns command-line startup and one exact root Agent identity, while `@deepseek-ai/dsh-tui` remains a presentation/input package that mounts onto an already created or resumed Agent.

Startup publishes either a fresh `main-session-<uuid>` identity or the requested `--resume` identity before the dependency-heavy runner activates. The runner waits for Loader settlement, installs the configured model selection during unpublished Agent setup, creates or resumes that exact identity, mounts the renderer, then removes the bootstrap selection so the TUI's `/model` controller is authoritative. Fresh setup resolves and records the effective default agent preset before mounting it; resume setup mounts `resolveSessionPreset(session)`, so a Web-originated session with a later durable blank-session switch regains that historical composition rather than today's default. The bundle disables every base model-facing row owned by the preset roster, so the selected preset is the only source of those capabilities and `minimal` does not inherit the standard/code stack. The prompt registry is a separately addressable `@deepseek-ai/dsh-tui/prompt` Loader row mounted before the runner. Normal startup requires TTY stdin and stdout and fails early otherwise; `--help` remains pipe-safe. Pipes and automation use the existing headless profile.

Settings and workspace state are Host-plane product services, not browser ownership. The TUI profile composes the same file settings provider and `ui-theme.preference` schema as Web plus the same JSON storage/domain/workspace registry stack. `/settings` is a redacted namespace/document hub rather than a clone of the Web React forms, and `/theme` mutates only the preference field so a redacted sibling secret can never be erased by section replacement. `/workspace` reads the durable registry and requests a fresh-session handoff; it never rewrites the bound session's immutable `SessionHeader.cwd`.

One CLI-owned process host implements both resume and fresh-workspace transitions. Bare `/resume` discovers persisted sessions through the full-viewport selector; `/resume <session>` bypasses discovery but passes the exact id through the same liveness, log, model-route, and workspace preflight. The renderer validates idle/session/directory state, flushes the current session, drains input, and releases pi-tui plus alternate-screen/mouse modes; the host then preserves the selected profile, patch stack, environment, and session argument while replacing the process in the destination directory (or supervising a foreground child on platforms without `execve`). All recoverable validation precedes committed teardown. A rejected pre-commit handoff re-enters terminal modes and forces a complete frame because pi-tui's previous-row cache otherwise belongs to the abandoned alternate buffer. The `start(cwd)` method is optional at the renderer seam, preserving resume-only custom embeddings even though the shipped host implements both methods.

The renderer is recovered from DeepSeek Harness's own pre-deletion history and ported to current APIs. Canonical `Session` events remain the sole durable conversation source: replay folds those events into committed terminal output, while live chunks, tool progress, questions, and approvals are transient projections. The TUI does not add another chat log or tool scheduler. It consumes the existing scoped command registry, Agent inbox operations, session query/reference services, skill registry, tool presenters, token meter, and model-selection seam.

The terminal command catalog includes Codex-shaped `/skills`, `/keymap`, `/vim`, `/fast`, `/experimental`, `/ide`, `/mention`, `/copy`, `/export`, `/diff`, `/rename`, `/init`, `/review`, `/new`, `/clear`, `/ps`, `/stop`, and `/approve` adapters without importing Codex runtime state. Skills remain Agent-scoped registry entries; Vim is an input-mode projection over pi-tui's editor; fast mode selects only an advertised route whose metadata identifies a low-latency variant and retains the prior route for a reversible switch. Experiments launch existing terminal actions instead of creating a second feature-flag store. IDE context degrades to terminal-host diagnostics, `@` references, and workspace handoff until an embedding supplies an IDE bridge; mention reuses that file-reference composer path. Copy selects the newest transcript-visible assistant Markdown and writes an OSC 52 frame, with tmux passthrough and a 100,000-byte pre-encoding bound. Export projects the complete human-visible transcript from a stable Session event snapshot, excluding injected context and model-only replacement nodes; it can copy that Markdown or publish it through a synced sibling temporary file and a no-clobber hard link. Diff reads the unstaged worktree plus no-index diffs for untracked, non-ignored files without mutating the index; it disables Git text conversion, external diff, hooks, filesystem monitors, and configured clean/process executables, and a presentation setting bounds each child process. Rename delegates title normalization, durable `session/title` recording, and pinning to the session-title service. Init and review admit repository-guidance and non-mutating worktree-review prompts as ordinary durable user turns only while the agent is idle; optional review instructions remain part of that logged message. New and clear both enter the existing fresh-process handoff for the current immutable workspace after an idle check and session flush; a missing or rejected host transition keeps the current session usable. The global `command-jobs` consumer maps Codex's background-terminal commands onto caller-visible active `ctx.jobs`: `/ps` uses non-consuming snapshots, while `/stop` requests cancellation only for `running` jobs and leaves `stopping` work alone. The human controller keeps task admission available independently of whether a preset exposes model-facing `job_*` tools, while registry owner checks prevent one session from listing or cancelling another session's jobs. Approve either settles the active queue entry as `allowed-once` or arms one next request whose tool and reason match the latest interactive rejection; a mismatching next request consumes the grant without receiving it, so the command cannot broaden the session policy or create a durable allowance. `/status` remains a session diagnostics projection and does not print the system prompt or registered-tool catalog.

Approval policy and execution remain owned by `ctx.approval`. The TUI registers only an exact-agent, FIFO answerer for `approval/request`, returning `allowed-once`, `rejected`, `cancelled`, or `unavailable`; the Approval service owns the durable `approval/asked` and `approval/decided` audit pair. The shared Permission service contributes `/permissions`. Bare `/permissions` opens a terminal selector over the service-owned preset table, while an argued invocation and every selection use the same command handler as Web. The dashboard and footer project the configured preset display name from that service. The shipped app maps `deepseek --full-auto` to the deployment's `workspace-write` + `never` preset and maps both `deepseek --yolo` and `--dangerously-bypass-approvals-and-sandbox` to `danger-full-access` + `never`; the runner pins the selected preset before publication. The command registry deliberately has no session-level startup shortcuts, so deliberate live changes remain under `/permissions`. `ctx.userQuestions` remains the independent structured-question provider. Both interaction queues share the renderer's modal queue without becoming lifecycle or policy authorities.

Terminal rendering keeps stable history separate from live projection, preserves pre-first-token and per-phase timing, renders tool-owned presentation intents, supports session resume and scoped skills, and restores raw mode on disposal. Submitted human messages remain as padded, label-free transcript cards and in editor history; assistant responses use a leading `•` without a role header, and visible reasoning uses `Think`. A live animated `Deep diving (<elapsed> • esc to interrupt)` row follows the active conversation tail and disappears when the durable turn settles. Interactive chrome uses one [selectable accent hue](2026-08-15-tui-accent-hues.md), defaulting to DeepSeek blue; state-bearing success, warning, and error roles retain their distinct colors. The compact first footer row omits idle state and cache rate because live progress appears in the transcript and the statistics row already owns cache hit rate. Width-keyed card caches avoid re-wrapping settled output on every frame, while one forward timing cursor serves every completed step footer without rescanning the complete log. Color-scheme, accent, or reasoning rebuilds retain the current streaming component and invalidate its timing cache, so a mid-turn redraw cannot lose accumulated response time.

Running-turn steering keeps an identity-keyed transient projection beside the durable Agent inbox. A submitted message is immediately visible in an ordered composer-top preview, then leaves that preview only when the same `MessageId` is claimed or discarded; the later durable `user/message` remains the sole transcript record. Escape with queued steering preserves the inbox, aborts the active call, and relocates the final next-step item to next-turn: this arms the post-abort driver while retaining batch order because Inbox claims next-step before next-turn. Escape without pending steering and Ctrl+C keep the existing discard-and-cancel behavior. Each message preview is bounded to three wrapped lines plus an ellipsis, and the footer count remains the compact queue summary.

The shipped presentation defaults to inline terminal scrollback. The terminal owns mouse-wheel scrolling and drag selection over the conversation, while keyboard Up/Down remains editor-history input. An explicit `fullscreen: true` enables a bounded viewport that follows new output until Page Up/Page Down moves away, then resumes tail-following when the user returns with Ctrl+End or reaches the newest page; `mouse: true` additionally enables SGR click and wheel handling. Alternate-screen and any enabled SGR mouse modes enter before pi-tui starts and leave only after it stops, and startup failure, normal disposal, and process handoff use the same restoration boundary. Ordinary built-in pickers occupy a dedicated composer-flow container immediately after the borderless composer, so they push the status rows down instead of covering the conversation center; blocking approvals/questions retain modal placement, while resume keeps its full-viewport browser. Slash, skill, file, and session-reference completion keep pi-tui's editor-owned selection state and input handling but project their rows through a separate component after the composer, avoiding a second completion state machine while matching the composer-attached layout. All placements still serialize through the same FIFO focus owner. The existing multiline editor, bracketed paste, and cursor-aware `@` completion remain the input authority. `/model`, Alt+M, and the optional footer mouse target all enter the same model controller, so the shortcut and visual affordance cannot diverge from command behavior. The selector renders the highlighted adapter's exact reasoning-effort choices as an explicit row, brackets the live choice, and supports forward/backward Tab or arrow navigation before Enter commits the model-and-effort pair. The detailed strip below that footer does not re-fold browser nodes: the TUI bundle mounts Web's `sessionStats` projection and combines its whole-log counts, LLM/tool time, TTFT, and decode duration with the shared disjoint token buckets. Its only terminal-owned behavior is one-line formatting, width elision, and theme-safe dim styling.

Direct `/model off`, `/model high`, and `/model max` reuse the current route's advertised reasoning-effort catalog. An unavailable level is rejected without changing the selection.

`/mcp [verbose]` projects only MCP-qualified schemas from the current Agent's scoped tool view. The projection reports public names and optional descriptions without claiming connection status that the tool registry cannot determine.

`/usage` records the existing shared session-statistics line in the transcript. It reports observed conversation timings and token buckets; provider account limits remain absent because no account-quota service supplies them.

A true zero-state session uses an adaptive split welcome card rather than stretching the compact transcript header across an empty viewport. Its composition borrows the left-identity/right-update rhythm of Claude Code while retaining only first-party DeepSeek content: the left column renders the official SVG-derived Braille whale in the terminal foreground and projects preset, model, permission, and workspace from their owning services; the right column names real Harness commands and the newest queryable sessions. The mark is black on light terminals without becoming invisible on dark themes, and its reduced tier avoids Kitty/iTerm image protocols. The first durable turn contracts the card to a product-only transcript header, so neither a banner subtitle nor a session id survives into conversation. The multiline composer and submitted human cards use the Web theme's exact light and dark user-bubble tokens selected by `/theme`; a separate bottom bar shows Goal, model, compact usage, context pressure, and queued work while leaving its default left side empty so workspace and branch do not consume conversation width.

Rich output remains terminal-native rather than importing the Web React tree. pi-tui's GFM renderer owns headings, emphasis, links, nested/task lists, blockquotes, tables, and fenced code; a narrow highlighter maps `diff`/`patch` metadata, hunks, removals, and additions to the same semantic palette used by tool diff cards. Adjacent hunks for one path form one visual group. KaTeX typesetting, fetched Markdown images, Shiki token coloring, copy controls, and horizontal scrollers remain explicit browser-only differences instead of hidden dependencies in the terminal package.

The package's base semantic version is rendered beside both welcome and compact product labels, avoiding a second handwritten version source. A pristine zero state allocates no empty transcript viewport and uses the fixed two-row composer gap instead of anchoring the input at the terminal bottom. The editor retains pi-tui's hardware cursor marker as the IME anchor and toggles a reserved one-cell software caret every 530 ms. Keystrokes and state redraws restart the visible phase, so terminals that ignore DECSCUSR still expose focus without shifting placeholder text. The shipped bundle keeps `showHardwareCursor` enabled instead of overriding the renderer default, ensuring the real `dsh tui` path actually mounts both cursor fallbacks. The timer starts after terminal acquisition and is cleared at the shared release boundary. Reasoning starts visible under `Think`; injected context renders zero compact rows and becomes visible only in expanded details. Ctrl+O, Ctrl+R, and `/details` remain available without mouse capture, while an enabled footer `▸`/`▾` mouse target drives the same state.

## Reference and provenance boundary

Gemini CLI and OpenAI Codex were studied for process-mode separation, terminal input routing, committed-versus-live rendering, approvals, resume, headless output discipline, and PTY testing. The current command names and behavior are pinned to OpenAI Codex commit [`22bf16a`](https://github.com/openai/codex/blob/22bf16a37ed45006c0226541874abd7449c29911/codex-rs/tui/src/slash_command.rs), with dispatch details from [`slash_dispatch.rs`](https://github.com/openai/codex/blob/22bf16a37ed45006c0226541874abd7449c29911/codex-rs/tui/src/chatwidget/slash_dispatch.rs), response and human-message presentation from [`messages.rs`](https://github.com/openai/codex/blob/22bf16a37ed45006c0226541874abd7449c29911/codex-rs/tui/src/history_cell/messages.rs), running-state timing from [`status_indicator_widget.rs`](https://github.com/openai/codex/blob/22bf16a37ed45006c0226541874abd7449c29911/codex-rs/tui/src/status_indicator_widget.rs), Goal footer timing from [`goal_status.rs`](https://github.com/openai/codex/blob/22bf16a37ed45006c0226541874abd7449c29911/codex-rs/tui/src/chatwidget/goal_status.rs), and clipboard limits from [`clipboard_copy.rs`](https://github.com/openai/codex/blob/22bf16a37ed45006c0226541874abd7449c29911/codex-rs/tui/src/clipboard_copy.rs). The `/diff` safety and untracked-file behavior was compared with Codex commit [`4861236`](https://github.com/openai/codex/blob/4861236f06d0df397436531b4aa3d7fa6975959c/codex-rs/tui/src/get_git_diff.rs); the running-input preview and Markdown transcript export were compared with Codex commit [`e5470f1`](https://github.com/openai/codex/blob/e5470f1bce099442d73e491ce63d189d355b061e/codex-rs/tui/src/bottom_pane/pending_input_preview.rs) and its [`transcript_export.rs`](https://github.com/openai/codex/blob/e5470f1bce099442d73e491ce63d189d355b061e/codex-rs/tui/src/app/transcript_export.rs). The MIT-licensed [`dsh-TUI`](https://github.com/ccch1mneyyy/dsh-TUI/tree/9a0559b820fb0a8733089560916dfeb75075c244) implementation was inspected for its slash-command catalog, queued-input verification, compaction projection, theme persistence, and launcher checks; its Ink renderer and rc.6 compatibility layer were not copied. Codex and Gemini licensing would permit attributed reuse, but this implementation copies no source from those repositories. Official Claude Code and the inspected all-rights-reserved source reconstruction contributed only high-level observable behavior, with no copied code or nontrivial expression. `@earendil-works/pi-tui` remains an explicit dependency with its local compatibility patch and generated third-party notice.

The restored TUI snapshot is first-party DeepSeek Harness source from commit `7248b5ec8f8769f882f12fd521504fa48e97bcf3`, immediately before deletion commit `10bb9cbf4a22b5095bb9ff04d1425907af8f08af`. At that point both the repository and `@deepseek-ai/dsh-tui` declared BSD 3-Clause. The repository-wide MIT adoption in `c905c4694e317eff1f529f0fed047c2ce202d11a` happened after the package had been deleted and therefore did not carry that historical snapshot through the mechanical package-manifest relicensing. The restored implementation retains its BSD 3-Clause terms; the current adaptations and additions are MIT-licensed. The combined package consequently declares the exact SPDX expression `(MIT AND BSD-3-Clause)`, and its package-local `LICENSE` preserves both notices and explains the boundary.

## Alternatives considered

**Keep Web as the only interactive product.** Rejected because the requested deployment is an interactive CLI and Web cannot satisfy terminal-native workflows, piping boundaries, or SSH/tmux usage.

**Put Agent creation inside the renderer.** Rejected because it makes a UI package a lifecycle authority, races Loader listeners, and prevents the bundle from proving exact create/resume identity before presentation mounts.

**Copy a complete external CLI frontend.** Rejected because those frontends couple to different runtimes and data models; Claude-family source also cannot be copied under its license. Reusing the Harness-owned renderer preserves native Session, Tool, Command, Approval, and Cordis contracts.

**Embed the Web React settings and conversation tree in a terminal shim.** Rejected because it would pull browser transport, DOM layout, and client-side state ownership across the Host boundary. The TUI instead consumes the same settings, workspace, preset, and session services and gives them terminal-native selectors and renderers.

**Make TTY detection silently fall back to headless.** Rejected because redirecting an interactive command would change its protocol and approval semantics. The explicit profile is the boundary: `tui` requires a terminal, `headless` is for automation.

The root slash catalog filters nested `skill:` rows until the explicit `/skill:` namespace is entered, leaving `/skills` as the command-sized discovery entry.

## Consequences

DeepSeek Harness once again has a supported interactive terminal product, invoked with `deepseek` or the compatibility spelling `dsh tui`, while `dsh web`, `--profile headless`, ACP, and other front doors remain independent. The product adds a renderer package, a shipped bundle, a pi-tui patch, terminal snapshots, and platform lifecycle obligations. A new Cordis service/catalog and package-publication surface must therefore remain generated and tested. The TUI is intentionally text-terminal only and has no cross-process session lock. The shipped CLI owns process replacement for `/resume` and `/workspace`; a custom renderer embedding that omits those callbacks degrades to warnings without changing the current session.
