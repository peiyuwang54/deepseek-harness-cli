# Agent Note：TUI 对话与工作区回退

状态：已实现

[English](2026-08-18-tui-workspace-rewind.md) | 中文

## 问题

终端可以分叉当前对话，却不能回到较早的人工消息，也不能撤销智能体轮次对工作区的修改。使用项目 Git 索引或创建真实提交会改变用户持有的仓库状态；恢复时删除所有未跟踪路径则可能移除被忽略或独立创建的数据。

## 决策

TUI 会在当前人工轮次首次顶层工具分发前，以及每次直接 `!command` 前捕获工作区。每个人工轮次一个检查点即可覆盖之后的嵌套和并行工具工作，并保证位于所有工具正文之前。检查点失败会阻止工具或 Shell 正文启动。

每个规范化工作区在 `$DSH_HOME/workspace-checkpoints/v1/<workspace-hash>` 下拥有一份影子 Git 仓库。其 ref、索引、配置、hook 目录与对象库和项目 `.git` 隔离；进程参数只把工作区设为 work tree。系统与全局 Git 配置、继承的仓库环境变量、hook、签名、自动换行转换和全局 attributes 均被禁用。影子树包含普通文件、符号链接与未忽略的未跟踪文件。可配置的单文件、总大小和子进程上限会在 `git add` 前拒绝不安全或无界捕获；特殊文件和嵌套仓库也会被拒绝。

`/rewind` 会选择一条历史直接用户消息，再选择恢复对话、文件或两者。对话回退会分叉到该消息之前的已完成轮次，并切换到持久子会话，原 Session 保持不变。文件恢复会先捕获当前工作区，确认每条已跟踪路径都位于规范化根目录下且父目录不是符号链接，再恢复目标树，并只删除安全树中存在而目标树中不存在的路径。忽略路径不会进入影子索引，也不会被删除。`/restore` 打开同一个选择器，并预选仅恢复文件。

Session 只记录影子提交 id、检查点种类和关联的人工消息序号。文件内容留在追加式日志之外，也不会进入模型上下文。

## 考虑过的替代方案

**在项目仓库中提交。** 拒绝，因为即使是临时 ref 和索引写入也会修改用户持有的 Git 状态，还可能触发仓库配置。

**恢复时运行 `git clean -fd`。** 拒绝，因为宽泛清理可能删除任何 Harness 检查点都不持有的未跟踪数据。

**为每个检查点复制完整工作区目录。** 拒绝，因为它会重复存储未修改内容、需要处理更多文件系统情况，也没有 Git 基于内容寻址的树恢复。

## 验证

文件系统测试使用真实项目仓库和独立影子仓库，证明已跟踪与未跟踪文件恢复、忽略文件保留、检查点持有的后建路径移除、真实 HEAD 和索引保持、符号链接按链接存储且不遍历目标，以及大文件准入失败关闭。TUI 集成测试会选择历史消息、选择仅恢复对话、flush 子会话，并覆盖宿主切换失败后的恢复。无密钥终端快照固定消息选择器。

## 结果

工作区回退需要 `git` 可执行文件，并占用 `$DSH_HOME` 下的本地空间。超过配置准入上限的工作区仍可用于聊天，但顶层工具会被阻止，直到工作区缩小、正确忽略相关文件或部署提高上限。即使之后的进程切换失败，恢复前的文件状态仍可通过安全提交找回。
