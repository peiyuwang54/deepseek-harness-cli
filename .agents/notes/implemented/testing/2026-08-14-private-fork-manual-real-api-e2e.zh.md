# Agent Note: 私有 fork 手动运行真实 API e2e

Status: implemented

[English](2026-08-14-private-fork-manual-real-api-e2e.md) | 中文

## 问题

私有 fork 继承了一个要求仓库 secret `DEEPSEEK_API_KEY_EXTERNAL` 的真实 API e2e 工作流。当 fork 有意不配置 Key 时，自动 push、PR 和每夜触发都会在预检查阶段失败，产生红色工作流记录和仓库所有者通知，却没有执行模型测试。

仅为让这些自动运行变绿而配置 Key，会增加凭据维护，并让普通仓库活动消耗外部 API 额度。无此运维成本的无密钥 CI 工作流已经覆盖构建、类型、单元测试和快照。

## 决策

[真实 API 工作流](../../../../.github/workflows/e2e.yml)只保留 `workflow_dispatch` 触发器。push、PR 和定时计划都不能启动它。只有当实时提供方证据值得投入凭据和 API 成本时，维护者才从 GitHub Actions 中主动启动运行。

现有预检查继续保持严格：手动启动但缺少 `DEEPSEEK_API_KEY_EXTERNAL` 的运行会在构建和测试执行前失败，不会因测试套件自行跳过而产生误报成功。工作流继续将 secret 限定在预检查和测试步骤，并固定使用 DeepSeek 公开 API 端点。

同一 ref 的并发手动运行会取消较早的运行。[真实 API e2e 设计说明](2026-06-19-real-api-e2e-ci.md)继续约定独立工作流、secret 映射、预检查和最小权限决策；本说明只约定私有 fork 的触发策略。

## 考虑过的替代方案

**配置 secret 并保留自动触发。** 这会恢复合并前、合并后和每夜实时提供方信号，但也会授权普通 push 和时间推移使用一个需要维护的外部凭据。私有 fork 不需要这种持续信号。

**把缺少 Key 视为成功跳过。** 这样可以避免失败通知，但无法区分真正请求的真实 API 运行与实际调用过提供方的运行。仅手动触发并保留严格预检查，可以保证结果真实。

**禁用或删除工作流。** 这样可以阻止所有意外运行，但会移除已纳入版本控制且可复现的主动实时提供方检查路径。仅手动触发在避免自动执行的同时保留了该路径。

## 后果

仓库活动不再产生真实 API e2e 失败或 DeepSeek API 用量。维护者必须配置 `DEEPSEEK_API_KEY_EXTERNAL` 并显式启动工作流，才能获得实时提供方证据。

该 fork 放弃了自动检测合并前、合并后和每夜外部 API 漂移的能力。重新引入任何自动触发器，都必须主动接受其凭据暴露、通知和 API 成本后果。
